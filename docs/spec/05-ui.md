# 05 — Interface

There are two front ends, and both drive the same state.

| Surface | Drawn by | Role |
|---|---|---|
| Menu bar item | Go, `fyne.io/systray` | Quick access |
| Control panel window | Swift helper | The full interface |
| Permissions window | Swift helper | First-run and on demand |
| Virtual lock | Swift helper | See [04](04-virtual-lock.md) |

## Why there is a window at all

The menu bar cannot be relied on. On a Mac with a notch, macOS silently drops status
items into the hidden region behind it once the bar is full, with no warning and no
overflow affordance. On a machine with a dozen management and security agents that is
not an edge case, it is the normal state.

An app whose only interface can vanish without explanation is not finished. The window
is the primary interface; the menu bar item is the shortcut.

`v-claw open` from the CLI raises the window, which is the escape hatch when the icon
cannot be seen.

## Permissions window

v-claw needs very little, and saying so plainly is worth a window. On a managed Mac
running EDR, an app that states what it will **never** request is easier to trust and
easier to get approved.

| Permission | Needed | Why |
|---|---|---|
| Notifications | yes | Announce a release, so a forgotten hold cannot stay silent |
| Accessibility | only for the global lock hotkey | Opt-in. Nothing else uses it |
| Screen Recording | **never** | v-claw does not read the screen |
| Input Monitoring | **never** | Idle time uses `CGEventSourceSecondsSinceLastEventType`, not an event tap |
| Full Disk, Camera, Mic, Contacts, Location | **never** | |

The Input Monitoring line is a design constraint, not just a claim. An event tap would
be the easy way to measure idle time, and it was rejected because it needs Accessibility
and looks like a keylogger to a reviewer.

Notifications go through `UNUserNotificationCenter` in the helper, because posting them
needs the app bundle's identity. An earlier version shelled out to `osascript`, which
posts as *Script Editor* and is silently dropped when that has no permission.

### Status line

The first item is not clickable. It is the honesty line, and it must always reflect what
was read back from the system, never what v-claw intended.

| Situation | Text |
|---|---|
| Active, lid blocking guaranteed | `AC Power - awake (full)` |
| Active, lid blocking best effort | `AC Power - awake (basic, lid best effort)` |
| Armed, on battery in auto | `Battery - armed, waiting for AC` |
| Off | `Off` |
| Timed | `AC Power - awake, 42m left` |
| A setting did not stick | `! Overridden - see Diagnostics` |

User-facing text says **basic** and **full**, never "tier 0" and "tier 1". A numbered
ladder would mislead on Linux, where lid blocking needs no privilege and both arrive at
once. The text comes from `Capabilities()`, so the menu never needs to know which
platform it is on. See [08-cross-platform.md](08-cross-platform.md).

### Tier 1 not installed

When the daemon is absent, a single extra item appears above Diagnostics:

```
  Enable lid-close blocking...
```

It opens a sheet that explains what will be installed, shows the exact three commands,
and offers two paths: install now with an admin prompt, or copy a request for an IT
ticket. See [06-build-and-install.md](06-build-and-install.md).

## Icon

The mark is the orange claw that props a laptop lid open.

### Menu bar assets are colour, not template images

macOS offers **template images**: one colour plus alpha, which the system tints black in
light mode and white in dark mode. v-claw does not use them.

A template would discard the colour signal, and colour is doing real work here: grey for
off, orange for holding, red for overridden. Orange reads on both light and dark menu
bars, so the usual reason to prefer a template does not apply.

Consequence for the code: call `systray.SetIcon`, never `SetTemplateIcon`.

| Asset | Format | Size | Colour |
|---|---|---|---|
| Menu bar | PNG `@1x` and `@2x` | 18x18 pt | full colour |
| App icon | `.icns` | 16 to 1024 px | orange |
| Lock window | SVG | vector | full colour |

### A hand, plus a status badge

The mark is a hand, after the printed claw that props a lid open. **The hand never
changes shape.** A mark that morphs between states is a mark nobody learns, so state
lives in a small badge at the bottom right instead.

| State | Hand | Badge | Meaning |
|---|---|---|---|
| Off | grey `#8E8E93` | grey, solid | v-claw changes nothing |
| Armed | orange `#F26722` | amber `#F5A623`, **hollow** | auto mode, on battery, waiting for AC |
| Active | orange | green `#34C759`, solid | sleep is blocked right now |
| Active, basic | orange | amber, solid | holding, but lid blocking is best effort |
| Overridden | orange | red `#FF3B30`, with a bar | something is overriding v-claw |

Three independent signals, so none is load-bearing on its own:

1. **Hand colour** — grey means v-claw is doing nothing.
2. **Badge colour** — green working, amber qualified, red broken.
3. **Badge fill** — hollow means armed but not holding; solid means holding.

Signal 3 is what keeps armed and active apart for a colour-blind user, and signal 1 is
what makes "off" obvious at 18 px where a badge is only a few pixels wide.

The badge sits in a gap punched through the hand with an SVG mask, so it reads as a
separate badge rather than a blob merged into the palm.

This icon is a safety device, which is why it gets three signals rather than one. See
[03-safety.md](03-safety.md).

The app icon is the hand alone, with no badge.

The bar in the active glyph is the lid. The claw holding it open is the whole idea.

### Sizing rules

- Design on an 18x18 pt grid, and keep 1 pt of padding on every side.
- Strokes at 1.5 pt. Anything thinner disappears on a non-Retina display.
- Snap to whole pixels at `@1x`. Blurry menu bar icons look broken.
- Test on light mode, dark mode, and a reduced-transparency menu bar.

### Pipeline

One hand-written SVG per state lives in `resources/icons/`. `make icons` renders the PNG
set with `rsvg-convert` or `qlmanage`, builds the `.icns` with `iconutil`, and writes
them into `internal/icon`, which embeds them with `go:embed`.

The binaries carry their own art. No runtime file lookup.

## Notifications

Sparing. Notifications that arrive often get ignored, and the one that matters must not
be lost in noise.

| Event | Notify |
|---|---|
| A timed override expired | yes |
| Released because the daemon watchdog fired | yes, this is a bug signal |
| A pmset write did not stick | yes, once per session |
| Normal AC plug and unplug in auto mode | no, the icon already shows it |
| Lock engaged or dismissed | no |

## Accessibility

- Give every menu item a full accessible label. `NSMenuItem` titles are read as-is, so
  the status line must read as a sentence.
- Never let colour be the only signal. Fill against outline carries the same state
  independently, and it must stay that way.
- Honour Reduce Motion in the lock window. No animation on the clock.
